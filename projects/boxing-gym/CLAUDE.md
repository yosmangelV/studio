Extends the root `CLAUDE.md`. These rules are specific to this application and take precedence over the root when they conflict.

## Project Context

Admin panel for a boxing school. Web app, mobile-first. Angular frontend consuming a Python FastAPI backend via a generated OpenAPI TypeScript client.

## Auth — Supabase Pattern

```typescript
// core/auth/auth.service.ts
@Injectable({ providedIn: 'root' })
export class AuthService {
  private readonly supabase = inject(SUPABASE_CLIENT);
  readonly currentUser = signal<User | null>(null);
  readonly isAuthenticated = computed(() => this.currentUser() !== null);
}

// core/auth/auth.guard.ts
export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  return auth.isAuthenticated() ? true : inject(Router).createUrlTree(['/login']);
};
```

Rules:
- `currentUser` is a signal — never a BehaviorSubject
- Guard is a function (`CanActivateFn`), never a class
- Auth state initializes in `app.config.ts` before routes resolve

## API Client Pattern

The TypeScript client is generated from the FastAPI OpenAPI spec. Never write HTTP calls manually.

```typescript
// features/students/data-access/students.service.ts
@Injectable({ providedIn: 'root' })
export class StudentsService {
  readonly students = signal<Student[]>([]);
  readonly loading = signal(false);

  async loadAll(): Promise<void> {
    this.loading.set(true);
    const { data } = await StudentsApi.listStudents();
    this.students.set(data ?? []);
    this.loading.set(false);
  }
}
```

Rules:
- Services in `data-access/` wrap the client — components never call `StudentsApi` directly
- State is signal-based — no observables from HTTP
- Regenerate client after backend changes: `npm run generate:api`

## Routing

```typescript
// app.routes.ts
export const routes: Routes = [
  { path: '', redirectTo: 'students', pathMatch: 'full' },
  {
    path: '',
    component: ShellComponent,
    canActivate: [authGuard],
    children: [
      {
        path: 'students',
        loadChildren: () => import('./features/students/students.routes'),
      },
    ],
  },
  { path: 'login', loadComponent: () => import('./features/auth/login-page') },
];
```

Rules:
- Auth guard at shell level — protects all features at once
- All features are lazy-loaded
- No eager loading except `ShellComponent` and `LoginPage`

## Testing

### Stack

- **Runner**: Vitest
- **Library**: `@testing-library/angular` — `render` API, no `TestBed.createComponent`
- **Interactions**: `@testing-library/user-event`

### Dummy components (presentational)

```typescript
import { render, screen } from '@testing-library/angular';
import userEvent from '@testing-library/user-event';
import { StudentListComponent } from './student-list.component';

describe('StudentListComponent', () => {
  it('should display students', async () => {
    await render(StudentListComponent, {
      componentInputs: { students: [{ id: '1', name: 'John Doe' }] },
    });
    expect(screen.getByText('John Doe')).toBeInTheDocument();
  });

  it('should emit select when student is clicked', async () => {
    const selectSpy = vi.fn();
    await render(StudentListComponent, {
      componentInputs: { students: [{ id: '1', name: 'John Doe' }] },
      componentOutputs: { studentSelected: { emit: selectSpy } as any },
    });
    await userEvent.click(screen.getByTestId('student-item-1'));
    expect(selectSpy).toHaveBeenCalledWith('1');
  });
});
```

### Smart (page) components

```typescript
import { render, screen } from '@testing-library/angular';
import { StudentsPageComponent } from './students-page.component';
import { StudentsService } from './data-access/students.service';

describe('StudentsPageComponent', () => {
  it('should show student list when loaded', async () => {
    const mockService = {
      students: signal([{ id: '1', name: 'John Doe' }]),
      loading: signal(false),
      loadAll: vi.fn().mockResolvedValue(undefined),
    };

    await render(StudentsPageComponent, {
      providers: [{ provide: StudentsService, useValue: mockService }],
    });

    expect(screen.getByText('John Doe')).toBeInTheDocument();
  });
});
```

### Rules

- Use `vi.fn()` and `vi.spyOn()` — not `jest.fn()`
- All elements that tests query must have `data-testid`
- Naming convention: `<feature>-<element>` e.g. `students-list`, `student-item-1`, `students-submit-button`
- Dummy → assert DOM and outputs; avoid accessing `component`
- Smart → integration test with real children; mock only services and external deps
- No `TestBed.createComponent`, no `ComponentFixture` at describe level
- Use `screen.getByRole` first, `screen.getByTestId` as fallback

### data-testid convention

```html
<!-- feature-element[-identifier] -->
<ul data-testid="students-list">
  <li data-testid="student-item-{{ student.id }}">{{ student.name }}</li>
</ul>
<button data-testid="students-create-button">New student</button>
```

## Domain Naming

Use boxing-gym domain terms, not generic ones:

| Generic | Domain |
|---------|--------|
| `user` | `student`, `member` |
| `item` | `student`, `order`, `class` |
| `data` | `studentProfile`, `paymentRecord` |
| `list` | `studentRoster`, `classList` |
